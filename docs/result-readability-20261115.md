# 核查结果阅读层次调整

日期：2026-11-15。本轮仅调整现有核查页面展示，不改变业务数据、Agent、提示词或输出格式。

## 判断与取舍

原始记录来自程序查询并保存的证据快照；事实摘要来自模型对材料的整理。两者功能不同，但无需同时默认展开。保留所有原文和摘要文字，将事实摘要默认折叠，既减少重复阅读，也保留复核入口。不通过删减提示词、截断原文或重新生成历史结果来缩短页面。

“本次核查依据”包含主报事、自动候选、人员补充的计划及其执行、现场检查记录。说明明确候选是否相关仍需核实，不能把显示在此处解释成已确认关联。

| 之前 | 现在 |
| --- | --- |
| 找到的相关记录 | 本次核查依据：整组默认折叠，保留逐条原文 |
| 关键事实与时间 | 事实摘要：默认折叠，说明由AI整理 |
| 初步判断 | 保留，较“初步研判”更通俗 |
| 仍不能确定什么 | 待核实信息 |
| 建议下一步 | 建议核查事项：包括具体检查、补充资料、联系相应人员 |

正常结果阅读顺序：状态与核查时间 → 初步判断 → 待核实信息 → 建议核查事项 → 本次核查依据 → 事实摘要 → 查询范围与限制 → 运行详情。后三项以及原始依据默认折叠；取证或模型失败时仍展示明确错误，查询范围自动展开。

主页面保留一行状态及核查时间。完整核查编号、模型名、依据截止时间保留在“运行详情”；历史选择器仅显示列表序号、时间和状态，真实选项值仍是完整编号，同秒结果也可分别选择。结果已保存时不再重复显示长成功提示；处理中、失败、网络不确定等提示继续可见。静态“待人员复核”徽标移除，避免失败记录旁仍显示待复核。侧栏重复核查提示合并移除，快捷工作入口保留。

原有查询范围警示保留。生成时快照、补充后可重新核查、不自动建立关联/结案/通知及正式审核尚未接入，集中到运行详情一处。状态、错误提示和引用链接保持可读；引用字体由14px调整为15px，不修改全站配色。

## 七个文件分别改什么

1. `templates/report-evidence.html`：调整上述区块顺序、标题、折叠及说明；居民原始报事和人工补充表单保留。
2. `static/agent-run-view.js`：显示简短状态时间；每次切换结果重置折叠；点击报事/计划/执行/现场检查引用同时展开原始依据父组；查询/地点引用沿用上一包的父级展开；清除旧事实和元信息。
3. `static/report-agent-runs.js`：缩短历史选项显示和成功提示，继续保留完整内部编号；仅文字及可见性变化，不改请求、幂等、重试和存储逻辑。导入渲染模块的缓存版本同步更新。
4. `static/agent-check.css`：本页状态提示、长编号换行及引用字号；无全站样式重做。
5. `tests/test_agent_run_view.cjs`：新增4项回归并更新现有断言，共28项。
6. `tests/test_report_evidence_pages.py`：新增1项阅读顺序/默认折叠/元信息位置检查，共10项；验证新脚本与样式缓存版本。
7. 本说明。
