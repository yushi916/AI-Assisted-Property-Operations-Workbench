# 执行记录 API 验收

日期：2026-11-03。使用合成数据，实际数据库版本为0004_execution_records。

## 已完成接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | /api/executions | 保存执行记录或重试同一次提交 |
| GET | /api/executions | 分页查询，可按plan_id筛选 |
| GET | /api/executions/{execution_id} | 按内部执行编号查询详情 |

首次合法提交返回201；同号同内容重试返回200和原回执；同号换内容返回409。
新记录的计划或明确点位范围不合法、已知执行时间晚于录入时间时返回422。
数据库繁忙返回503，保留原编号和内容可重试。
输入校验拒绝客户端提供id、recorded_at、version。

执行点位按计划明确登记的地点ID校验，未知点位保留为空列表。
completed表示填报人的完成声称，后续仍需结合巡查和其他证据核对。
未知声称时间保留为null，录入时间由服务端另行生成。
查询计划的全部执行时包含未知点位记录。
筛选的计划不存在返回404；计划存在但暂无执行记录返回200和空列表。
列表先筛选计划，再按recorded_at、id倒序排列并分页，每条记录保留完整点位。
