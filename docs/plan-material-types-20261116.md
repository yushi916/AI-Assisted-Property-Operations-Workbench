# 安排、执行填报与现场观察：类型和引用说明

2026-11-16。用户反馈上一批网页端测试通过，本轮仍容易混淆材料类型，故仅做展示调整。

## 当前实现的正确理解

计划要求记录安排做什么，owner_name是计划负责人，不是发布人身份。执行记录记录人员填报的处理情况；现场检查记录记录人员在某时、某地点的观察。两种记录独立保存，计划覆盖多个地点不表示某一次执行或检查到达全部地点。

缺记录提醒来自本次核对的地点coverage数量。计划引用说明为什么需要核对该地点的工作要求，不证明工作未开展或未完成。已有现场检查可以对照，但不自动抵作执行记录。

## 最小展示改动

- “本次核对依据与原文”的每条summary都有固定文字标签：计划要求、执行填报、现场检查，不靠颜色区分。计划名称含“检查”也不会改变它的类型。
- 原文仍按需读取。未读取时显示类型、已知地点及“展开后查看”提示；读取且版本匹配后，计划显示名称、计划起止日期时间、负责人；执行填报显示完成时间及执行人（未填报完成时显示工作开始时间）；现场检查显示观察时间及检查人。
- 日期包含年份和年月日，明确北京时间，跨日两端各显示日期；未知时间保持未知，不拿录入时间或计划时间代替。
- 原文地点标签分别为计划覆盖地点、本次填报工作地点、本次观察地点，完整地址、编号、版本继续保留在详情。
- 缺记录提醒先展示“本次查询结果：本地点执行记录N条、现场检查记录M条”，再显示“对照计划要求”链接及其用途。数量直接来自本次coverage，不从其他地点或点击后原文补算。已有检查时，提示核实是否已开展、是否漏填或未注明地点、是否仍有要求待落实，不一概建议再检查。
- 两地点仍共用原来的数量表，不新增两组地点折叠区。提醒里提供跳到该表标题的链接。原规则提示保留在提醒内默认折叠的“查看规则原始提示”中，便于比对，未覆盖API原始数据。
