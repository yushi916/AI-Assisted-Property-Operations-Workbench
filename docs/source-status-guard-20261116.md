# 来源状态一致性窄检查：本轮修改与验证

本轮只增加保存前的程序检查。没有修改提示词、模型配置、输出 schema、数据库、网页或取证规则，没有新增真实模型调用。它能拦截一部分来源状态矛盾，不能证明模型生成质量已经改善。

## 原始问题与处理

保留核查 `c4a3541a-7e00-48e8-bc1d-3413701b31df` 的完整原输出和证据快照。快照中维修工单为 `unsupported`、数量未知；原输出却说“没有查询到相关候选计划或历史工单记录”。计划查询为空可以支持前半部分，不能支持工单已经查询但没有记录。

这是来源状态与证据不一致，另有工单结论的引用覆盖不足。不是取证遗漏，也不能据此判整份输出全部错误。原始观察及现场核对字迹建议仍有其合理性。

修改前两项离线测试用于证明旧校验会放过该输出。修改后，同一份输入和输出触发 `SourceStateConflictError`，通过既有路径记为 `failed / validation`。不自动改词、补引用或重试。过去已保存的结果仍按原样读回，不回写其状态或正文。

## 判定边界

仅比较无额外子范围的 `search:<source>` 状态。来源明确为 `unsupported`（未接入）、`not_queried`（未查询）、`failed`（查询失败），正文又以已识别句式直接声称“未查到／查询为空／0条”时才拦截。覆盖观察、候选判断、待核实信息与建议文本。

| 表达与材料 | 本轮处理 |
| --- | --- |
| 工单未接入，却断言“未查到维修工单” | 拦截 |
| “未查到候选计划或历史工单记录”，计划为空、工单未接入 | 按来源分别核对，拦截工单部分 |
| “未查到候选计划；维修工单尚未接入” | 允许通过这道检查 |
| “不能把尚未接入说成没查到工单” | 不作为查无记录断言 |
| 条件句、问句、明确引述原话 | 在已识别语法内保守放行，留给人工复核 |
| 来源 `found / empty`、缺失状态或带计划子范围的查询 | 不由这道检查推断矛盾 |

不是简单判断某几个关键词是否同时出现。完整来源名列表必须能解析；无法确认语法或前文限定关系时放弃判断。开发中发现按逗号拆句会误拒“不能这样表述，未查到维修工单”等表达，已补充跨逗号的否定、条件与引述范围处理，并加入回归测试。

## 仍未解决的情况

- 漏引、引用是否真正支持每项事实、事实范围扩大、复杂时间推理、建议完整性等仍需原有检查和人工评审；本轮没有实现通用语义校验。
- 英文、隐含来源、未登记别名、跨句省略、复杂限定或否定可能漏检或产生未测误判。例如“工单：没有记录”“已查询维修工单，结果为空”“由于没有查到维修工单，需要现场核查”均未识别。保守跨逗号范围处理也可能放过后续独立错误句。这些限制明确保留，不继续追加规则以追求表面全覆盖。
- `found / empty` 状态下的数量和具体子范围矛盾，以及不同计划查询范围，不在本轮检查范围。
- 既有校验失败存储只保留证据和错误类别，不保存无效模型正文。本轮未扩展存储；本次历史坏输出已另行冻结保存。不能宣称产品已有完整失败原文审计或人工修正保存能力。
- 原始错误结果不会被本补丁自动修复；不能因旧网页仍显示旧文本，就判定新校验没有生效。
