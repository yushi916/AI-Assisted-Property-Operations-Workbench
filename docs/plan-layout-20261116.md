# 工作计划与计划记录核对：页面收尾

2026-11-16。本批承接现场检查页更新，不调整项目结构、数据接口或 Agent。

## 这次改了什么

- 工作计划页采用已有公共布局：先看计划列表，新增表单默认折叠，顶部按钮可展开。存在已恢复的提交、保存回执或存储错误时自动展开，不隐藏待处理状态。
- 列表四个入口分别为“计划详情 / 执行记录 / 现场检查 / 记录核对”，分成两列排列。计划详情查看工作要求，执行记录是工作人员填报，现场检查是人员观察，记录核对是程序比较已有记录。
- “计划核查”页面改名“计划记录核对”，明确不调用 AI，也不代替现场检查或完工验收。先展示需要核实的信息，再展示地点记录数量和时间先后；记录编号、版本和核对时间可展开查看。
- 执行页原有交叉链接同步改为“计划记录核对”。
- 表单使用“计划覆盖地点”，明确其与实际执行、检查地点不同。计划类型仅分类，不是自动重复排班。地点多选控件保持原样。

## 改动文件

展示：templates/plans.html、templates/plan-evidence.html、templates/executions.html（一处链接文字）、static/plan-pages.css（新增）。

验证：tests/test_plan_pages.py、tests/test_plan_evidence_pages.py、tests/test_plan_navigation.cjs（新增）；以及本说明。共11个文件。

## 验证与边界

本地相关 Python 测试34项、JS测试21项通过。覆盖页面字段、路由参数、静态资源、四个入口对应同一计划、表单展开不重置不提交、多地点与北京时间保存、待确认提交原样重试、刷新恢复回执、存储错误阻止提交、规则核对失败及恢复。JS21项包含既有执行导航3项、核对展示12项和新增计划交互6项。

没有改API、数据库模型、规则核对算法、Gemini提示词或SDK，没有真实模型调用或用户数据库写入。本批没有重复全量测试；不能把这些定向测试写成全项目验收通过。浏览器视觉与实际导航仍待用户本地验收。

已有观察、原文、地点ID、记录版本和历史AI快照保留；核对页读取当前记录，不能把它当历史AI快照。未查到记录不代表没开展工作；有记录不代表完工验收合格。
