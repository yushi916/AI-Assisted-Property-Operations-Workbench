# 报事与计划人工关联：接口与验收

日期：2026-11-06。使用合成数据。

## 业务含义与范围

人员将居民报事关联到某次具体计划，并保存填报姓名、关联理由与服务器时间。
关联表示需要共同核查，不直接证明同一原因、计划未完成或执行记录虚假。
报事、计划、执行和巡查记录分别保留，不因建立关联而改写。

新关联要求服务类别相同，报事地点已知且属于计划明确覆盖的地点 ID。
本版本不自动展开地点层级；观察时间不在计划窗口内，仍可由人员写明理由后关联核查。
linked_by 当前是填报姓名，尚不是经过身份认证的操作人。

## 接口与编号

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/api/service-requests/{report_id}/plan-links` | 建立关联或原样重试 |
| GET | `/api/service-requests/{report_id}/plan-links` | 分页查询该报事的关联 |

下表针对关联接口返回的单个 JSON 对象：

| 字段 | 含义 |
| --- | --- |
| id | 关联记录编号 |
| report_id | 被关联的报事编号，等于报事接口返回的 id |
| plan_id | 被关联的计划编号，等于计划接口返回的 id |
| request_id | 本次关联提交编号，用于重试与冲突保护 |

首次合法提交返回 201；同编号同内容返回 200，返回同一关联的当前状态。
同编号换内容、换报事，或用新编号重复建立同一有效关联，返回 409。
输入不合法、父记录不存在、类别或明确地点不符合要求，返回 422，整笔回滚。
写入繁忙返回 503，可保留原编号和内容重试。
查询失败返回 503，不以空列表代替；列表按关联时间与 id 降序分页。

## 撤销与重新关联验收：2026-11-06

POST `/api/service-requests/{report_id}/plan-links/{link_id}/revoke` 撤销指定关联。
link_id使用关联回执的id；撤销请求的request_id单独保存为revocation_request_id。

仅当前有效关联且版本符合时更新；原样重试不重复增加版本，冲突返回409。
撤销保留原创建编号、人员、理由和时间，另存撤销提交编号、人员、理由和时间。
