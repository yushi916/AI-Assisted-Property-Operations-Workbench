# 报事录入与列表：首版网页收尾第一批

2026-11-16。仅前端显示和导航；不改数据库、API、自动检索、模型提示词或证据规则，不调用真实模型。

## 为什么先做这两页

首版演示需要让观看者沿着“报事→核查→依据→补充记录→读回历史”理解业务。现有详情核查页和执行页已有公共蓝色布局，但报事录入、列表仍是独立旧布局；保存回执没有直达对应报事核查的入口，列表要先展开原始详情再找核查链接。这些问题影响主流程展示，适合小范围收尾。

参考岗位对交付的要求，而不把所有招聘技术词都变成项目功能：

- Siemens香港AI Engineer – Digital Development Centre（公司发布的LinkedIn招聘页，本次可读）：提到制作简单人机界面原型、向团队演示，及测试、日志、可追溯性。任职正文接受相关项目与最多3年经验；页面自动seniority标签与正文不一致，不能仅凭标签判断岗位级别。尚未从其官网搜索到对应精确岗位，不将转载站当官方确认。
  https://hk.linkedin.com/jobs/view/ai-engineer-digital-development-centre-at-siemens-4484552051
- Singtel/Nxera新加坡AI Solutions Engineer（官方招聘页，2026-11-02）：提到业务需求落地、API/数据库集成、评估、演示与UAT。要求3–5年经验，仅参考交付任务，不作为用户目前初级投递门槛。
  https://groupcareers.singtel.com/job/AI-Solutions-Engineer-Nxer/1365526966/

这只是少量职位的初步核对，不代表整个SG/HK市场，也不代表已确认用户的学历、语言、身份或年限符合。完整岗位匹配和CV草稿仍待下一步，不因这批网页工作延期到全站美化完成。

## 改动文件与范围

| 文件 | 改动 |
| --- | --- |
| `templates/index.html` | 报事录入复用公共布局、导航、表单样式；保存回执增加“查看详情与核查”链接；保留所有业务字段及ID |
| `templates/reports.html` | 列表复用公共布局、表格、分页及原文详情样式；说明主操作 |
| `static/reports.js` | 仅保存成功时显示入口，使用保存回执的报事ID；刷新恢复已接受回执后入口仍对应该记录；录入下一条时清除链接 |
| `static/report-list.js` | 每条列表直接提供该报事的核查入口；保留“展开原始报事”按钮及已有详情内容 |
| `static/report-pages.css` | 只作用于这两页的少量样式，窄屏表格内部横向滚动 |
| `tests/test_report_pages.py` | 检查实际渲染模板中的字段、唯一ID、脚本顺序、默认隐藏的回执入口及公共资源 |
| `tests/test_report_location_picker.cjs` | 在已有位置/重试测试上增加回执入口绑定、刷新/新录入状态，以及每行对应报事链接检查 |
| 本说明 | 修改透明说明、验证结果、当前验收步骤与后续范围 |

公共`layout.html`、原`workbench.css`、地点选择组件、位置ID、原始描述、观察时间/接收时间、风险声明和幂等提交规则均保持。新增链接只导航，不自动生成核查或建立关联。旧网页已保存的sessionStorage记录不清除。

## 当前用户步骤

将包内文件按同名相对路径复制到项目，现有文件覆盖、CSS和本说明新增；不要替换数据库。先仅运行：

```bat
python -m unittest tests.test_report_pages -v
node --test tests/test_report_location_picker.cjs
```

预期Python 3项、JS 13项。当前终端若没有node，先反馈，不为本轮升级环境或重配业务数据。通过后再做本地网页验收；当前不要额外录一轮供水/保洁案例，也不必点AI。

网页验收下一步会检查：两页与已验收详情页导航/字体/按钮一致；现有报事列表直接进入核查后仍是原报事；已保留的成功回执可进入同一报事；原始记录展开/分页正常。若要验证新保存路径，只需一条明确标注用途的虚构演示报事，不重复已完成的模型语义案例，具体下一步另行给出。
