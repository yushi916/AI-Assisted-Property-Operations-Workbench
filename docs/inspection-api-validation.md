## 业务规则

- 巡查关联一项计划，不要求先存在执行记录。
- 一条巡查对应一个明确地点；地点或观察时间未知时保留 null。
- 明确地点必须属于该计划的 PlanLocation，按地点 ID 精确检查，不展开父子范围。
- finding 描述填报的观察，不直接判定计划履行、责任或记录虚假。
- 新记录的已知观察时间不得晚于服务端录入时间；两种时间分别保存。
- 原始描述保留；客户端不能指定 id、recorded_at 和 version。

## 接口与提交语义

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | /api/inspections | 保存巡查或重试同一次提交 |
| GET | /api/inspections/{inspection_id} | 使用保存回执的 id 查询详情 |
| GET | /api/inspections | 分页查询，可按 plan_id 筛选 |

首次合法保存返回 201；相同 request_id、相同内容重试返回 200 和原回执。
同一编号提交不同且格式合法的内容返回 409，不覆盖原记录。
输入、关联范围或新记录的观察时间不合法时返回 422；数据库繁忙返回 503。
422 明确拒绝后可沿用原编号修正；结果未确认时保留原编号和原内容重试。

保存使用单一事务。新增记录的范围检查或回执构造失败时回滚。
已有提交重试不重新套用当前时钟和计划范围，不把历史保存改成一次新提交。
这项重试保护不等于未来履约建议的证据有效性检查。

列表 limit 默认 50，允许 1～100；offset 默认 0，必须非负。
按 recorded_at 降序、id 降序返回；当前列表未实现跨请求固定快照。
按计划查询保留地点和观察时间未知的记录，排除其他计划的记录。
计划存在但无巡查时返回 200 和空列表；指定不存在的计划返回 404。
分页响应只表示该页，不能作为整项计划证据已全部收集的证明。
