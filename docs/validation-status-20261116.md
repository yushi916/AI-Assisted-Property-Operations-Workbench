## 哪些边界已有验证

| 能力 | 已有证据 | 仍保留的限制 |
| --- | --- | --- |
| 正常受理及读回 | 报事、计划、执行和检查接口测试；使用者网页验收 | 没有真实物业生产接入或用户试点 |
| 保存与重复提交 | 同编号同内容返回原记录、换内容冲突、数据库繁忙及网络结果不确定的回归 | 浏览器草稿使用当前标签页 sessionStorage，不保证关闭标签页后恢复 |
| 地点适用范围 | 地点层级、明确执行/检查点位、未知地点、同名房间等程序测试 | 同一台账地点仍有冷热水侧、入口/电梯前等原文细部，需要内容评审 |
| 时间及未知信息 | UTC 保存/北京时间展示；观察与录入时间分开；未知时间、记录先后及相关检索窗口测试 | 接收时间只可作检索参考；不得补成实际观察时间，不能由先后直接认定复发或责任 |
| 失败处理 | 取证、请求、输出校验失败；SDK 模拟 HTTP、超时/异常响应和幂等相关测试 | 没有生产可靠性或自动故障恢复承诺；未完成运行记录的所有运维场景 |
| 新旧证据快照 | 保存后读回、补录不改旧结果、引用使用旧快照的接口/交互测试和使用者确认 | 不会自动把新材料合入旧结果；不是完整版本审计平台 |
| 事实忠实性 | W1/R1 历史复测、H1/H2 冻结材料逐条对照 | 仍有范围歧义及表达层次问题；固定案例改善不等于泛化稳定 |
| 引用 | 动态 schema 的引用枚举、应用层引用键检查、候选覆盖；逐条引用和全快照对照材料 | 编号有效不保证引用支持正文，也不保证正文全部事实都有引用；漏引未解决 |
| 来源状态 | 本次窄检查拦截已识别的“未接入/未查/失败却称查询为空”表述 | 只覆盖有限中文句式和明确来源状态，不是通用语义防护；详见[本轮说明](source-status-guard-20261116.md) |

程序测试、SDK 模拟响应、模型辅助评审与使用者人工确认分别记录。产品中的 `pending_review` 是待人工复核状态；当前没有正式审核、人工修改建议保存、审批审计或自动结案功能。离线 HTML/JSON 评审材料不能代替这些产品能力。

## H1/H2 的结果如何表述

| 案例 | 要验证的实质范围 | 使用者已确认的问题 |
| --- | --- | --- |
| H1：同一洗手盆冷热水 | 冷水正常记录不能证明居民反映的热水侧正常；未记录热水不等于未检查热水 | 第一次候选判断引用覆盖不足；第一次待核实表述有范围歧义，不判已确认事实扩大；两次建议基本可用，但未明确核对是否已有遗漏填报的检查 |
| H2：同一大堂不同部位 | 入口正常不能证明电梯前干净；清洁后观察到污渍不能直接确定复发或此前未清理 | 第二次待核实表述混淆清洁效果与检查范围的层次，不判已确认归责或复发；两次建议基本可用，但未明确核对完成后的变化 |
