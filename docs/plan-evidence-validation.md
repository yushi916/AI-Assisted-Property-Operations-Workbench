# 计划证据核对：实现与验证

日期：2026-11-05。全部业务验收使用合成数据。

## 业务范围

按一次明确计划，联合读取计划范围、执行声称与独立巡查，提示缺失信息和时间关系。
地点按明确 ID 精确核对，不自动展开父地点，也不把未知点位当作覆盖全部计划。
核对结果用于人员复核，不自动批准履约、判定虚报、派工或调用模型。

## 文件职责与调用关系

| 文件 | 职责 |

网页为 `/plan-evidence?plan_id=<计划编号>`。
只读接口为 `GET /api/plans/{plan_id}/evidence-check`，Swagger 分组为 plan-evidence。
网页路由只提供页面；证据 API 负责读取与核对。浏览器不重新计算业务时间关系。

## 核对规则

- coverage 列出明确关联到每个计划点位的执行和巡查；有记录不等于验收合格。
- due 表示核对时刻达到或超过计划截止；到期且缺明确记录时提示补查，不直接认定未履约。
- 未知点位、未知时间和未声称完成的反馈均保留，分别提示核实。
- 同点位的每条 completed 执行声称与每条巡查逐组比较，使用 observed_at 与 claimed_finished_at。
- before、same_time、after、unknown 分别表示观察早于、同一时间、晚于声称完成、时间不足。
- recorded_at 仅是登记时间，不代替观察或声称完成时间；完成后发现垃圾仍需考虑再次产生。
- evidence 包含计划及全部相关执行、巡查的编号与版本，包括点位未知的记录。
- 提示的 location_id=null 可以表示记录整体提示，不必然表示该记录的地点未知。

## 读取与页面可靠性

API 不借用分页列表，不按完成状态或录入时间过滤证据。
计划不存在返回404；无效 UUID 返回422；数据库读取失败返回503，不作为空结果。
成功响应使用 Cache-Control:no-store。本轮核对不写业务表、不增加记录版本。

网页刷新时隐藏旧结果；证据查询失败、超时或结果不匹配时提示未完成，允许重试。
地点名称查询失败时仍保留证据中的地点编号，台账缺项也不丢弃证据。
外部文本通过 textContent 显示。未知点位证据单独保留，不补入具体点位覆盖。
